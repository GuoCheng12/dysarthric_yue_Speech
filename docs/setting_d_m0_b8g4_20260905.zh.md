# Setting D：8×4 Real-only M0 重训结果

## 结论

2026-09-05 完成。新路径本轮最佳 M0 为 **checkpoint-50**；训练在 step90 因连续明显 dev 退化自动停止，没有跑满140步。

新 M0 dev 逐句平均 CER **19.3413%**，test **24.6330%**。旧1×32 baseline对应19.0006%和24.5895%；新旧test差约+0.0435个百分点。这是新训练路径的统一起点，不是声称超过旧baseline的性能改进。

## 数据与训练设置

使用冻结的 Setting D（seen-patient / globally unseen-content），不是旧 Setting C，也不是 dev+test 合并的探索协议。

| split | 语音 | 患者 | 唯一 content |
|---|---:|---:|---:|
| train | 2117 | 66 | 48 |
| dev | 258 | 36 | 6 |
| test | 253 | 33 | 6 |

核对三份JSONL的原始SHA-256；两两无utterance、content、规范化文本和Jyutping标识重叠，dev/test患者均属于train患者。vlink201、203、225、243、vlink_Kaho及指定vlink211噪声样本不在其中。

- 原始 `/data/qwen3-asr/models/Qwen3-ASR-1.7B` 初始化，新建LoRA；没有继承旧M0。
- 仅2117条real，不加入24条处方语音或其他synthetic。
- micro-batch=8，grad_acc=4，有效batch=32；BF16、SDPA，不启用gradient checkpointing。
- r=16，alpha=4，dropout=.05；q/k/v/o/gate/up/down目标后缀，共268个Linear、19,791,872个可训练参数，与旧baseline范围一致。
- lr=2e-4，linear scheduler，warmup=.02，seed=42；计划上限140step，保持旧baseline的scheduler预算。
- DataLoader workers=2、pin/persistent=true、prefetch=2。本次训练、teacher-forced dev loss及独立解码均成功。
- 每10step保存和全量dev解码；只按dev逐句平均CER选择M0，平局保留较早者。step>=40且连续3个检查点均比历史最优差至少2个百分点时停止。
- 先写入M0选择与权重哈希，再对选中模型做一次test解码；test未参与本次选择。

## 代码修复与验证

1. 正式collator两次processor调用显式right padding，使prefix遮罩位置正确。真实Qwen processor的8条批量监督token与分别单条处理逐token一致。
2. Trainer逐句计算有效target token的平均CE，再除以整个梯度累积窗口的实际句子数。不是micro-batch内token平均，也不会对最后不足32条的窗口使用错误分母。
3. `model_accepts_loss_kwargs=True`现在表示自定义compute_loss确实使用了整个窗口的utterance分母，并阻止Trainer再次除以累积步数；不是恢复此前“传入但模型未使用num_items”的bug。
4. 正式单卡入口明确禁用不使用的DeepSpeed unwrap探测，不安装或变更系统CUDA环境。

梯度测试覆盖32、29、5条不同长度样本，以及micro-batch1/8/16/32分组，均匹配显式逐句平均目标；全部 **201项测试通过**，相关文件Ruff通过。

旧baseline的批量teacher-forced eval_loss受到旧padding遮罩影响，不能与修复后的dev loss直接比较。本报告的新旧性能比较使用解码CER。
